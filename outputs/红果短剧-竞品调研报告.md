# 红果短剧调研报告：为什么只有前3集 & 竞品全集方案分析

> 调研员：general-purpose-1 | 日期：2026-10-10

---

## 一、问题1：红果短剧为什么很多剧只能看前 3 集？

### 1.1 红果的免费/付费模式
红果短剧采用 **IAA（应用内广告变现）模式**，而非传统 IAP（按集付费）：
- **官方定位**：全场免费，看广告解锁剧集，平台靠广告分账赚钱
- **实际运营**：并非所有剧都免费——
  - 新剧/热剧前 3 集免费，第 4 集起需看广告解锁或引导至 App
  - 老剧/二轮剧/独播剧确实可全集免费看
  - 红果官方从未承诺「所有剧全集免费」，宣传语是「海量短剧免费看」

**信息来源**：
- 今日头条用户反馈：「电脑上看红果只能看前三集，第四集开始都上了锁，点开就跳二维码：扫码进入App端，免费看全集」
- php.cn：「热门剧集采用『分集追更+全集解锁』双轨模式，前3集免费开放，后续集数需完成当日观看任务或连续签到解锁」
- 新华网（2024-11）：红果是 IAA 模式，「不花钱，花半分钟即可解锁一集」

### 1.2 官方 App 能看全集吗？走什么接口？
**是的，App 能看全集（看广告解锁）**，这是核心商业模式。网页端是引流版只放前 3 集。

**技术接口**（GitHub `kiocou/ttv-short-drama`、`yinjg1997/hongguo` 抓包分析）：
| 层级 | 技术细节 |
|------|---------|
| 接口域名 | `*.novelquickapp.com`（字节系） |
| 核心接口 | `/novel/player/video_model/v1`、`/novel/player/multi_video_model/preload/v1` |
| 签名机制 | X-Argus / X-Gorgon（native 层 SO 库计算，几分钟过期） |
| 请求加密 | 请求 body 加密二进制，响应明文 JSON |
| 设备指纹 | device_id、iid、aid=8662、app_name=novelread |
| 登录态 | x-tt-token / cookie |
| DRM | main_url 直接返回，CDN 防盗链（Range 3 路竞速） |

### 1.3 网页版是「引流版」？
**确认。** hongguoduanju.com 是品牌展示+引流下载 App；novelquickapp.com 才是实际内容服务。网页版只放前 3 集是**产品策略**（App 端才有广告变现 SDK），不是技术限制。

### 1.4 技术上能否拿到全集？
**能，但成本高且不稳定**：
| 方案 | 原理 | 可行性 | 风险 |
|------|------|--------|------|
| Frida 签名预言机 | 模拟器跑 App，Frida hook 让 App 自算签名，Python 调用 | ✅ 已验证（yinjg1997/hongguo） | 依赖模拟器常驻，App 更新即失效 |
| redroid Docker | Android in Docker 部署签名服务 | ✅ 可行 | 需内核 binder 模块 |
| 网页版 m3u8 提取 | 抓 player_aaaa JSON 提 m3u8 | ⚠️ 仅限前 3 集 | 第 4 集起网页无数据 |
| 第三方 API 服务 | 付费 API（cenguigui.cn） | ⚠️ 不稳定 | 法律风险高 |

## 二、问题2：竞品怎么做到全集可看？

### 2.1 各竞品数据源
- **河马剧场**（点众）：自有 IP + 500+ 版权方合作 + 「河马合伙人计划」（与爱奇艺/红果/九州联合制作）
- **九州短剧**：九州文化自制 + 外部版权采购
- **点众快看**：自有 IP 改编 + 版权合作（有视听许可证）
- **ReelShort**（中文在线出海）：全原创英文内容，洛杉矶制作，买断制 $150K–250K/部
- **DramaBox**（点众出海）：国内短剧翻译出海 + 海外自制
- **TVBox/影视仓**：空壳 + 第三方 maccms 采集接口
- **OmniBox/MoonTVPlus**：开源自建聚合，用户自配 maccms API

### 2.2 核心：采集站为什么有全集？
maccms（苹果CMS）V10 提供标准 JSON API（`/api.php/provide/vod/?ac=videolist`），返回 `vod_play_url` 播放直链。

**采集站数据来源**：
| 来源 | 说明 | 占比 |
|------|------|------|
| 官方平台爬虫 | 爬红果/河马/九州 **App 端**（非网页端）视频直链，转存自家 CDN | ~60% |
| 盗版站互采 | 采集站间「联盟采集」互相爬 | ~20% |
| 版权方泄露 | 审核/后期环节流出 | ~10% |
| 用户上传/UGC | Telegram/网盘搬运 | ~10% |

**关键洞察**：采集站能拿到全集，是因为爬的是 **App 端**（App 能看全集），用模拟器+脚本批量爬播放地址，转存后通过 maccms API 对外提供。采集站间形成「资源网络」——一站率先爬取，其他站跟进。

**法律风险**：采集站多无版权授权（盗版）。2025 年嘉兴已有刑事判例（爬海外短剧上传盗版 App，判侵犯著作权罪）。服务器多在境外打击难。

### 2.3 「全集可看」5 条路线
| 路线 | 代表 | 合法性 | 稳定性 | 成本 |
|------|------|--------|--------|------|
| A. 官方授权 API | 河马/九州 | ✅ | 高 | 高 |
| B. 自有版权+自制 | ReelShort/点众 | ✅ | 高 | 极高 |
| C. 爬虫+签名机 | GitHub 开源 | ❌ | 低 | 中 |
| D. maccms 采集站对接 | TVBox/OmniBox/MoonTVPlus | ❌ 灰色 | 中 | 低 |
| E. 第三方聚合 API | cenguigui.cn | ❌ 灰色 | 低 | 低 |

### 2.4 给我们的建议
**分阶段**：
- **第一阶段（MVP）**：路线 D——接入 3-5 个稳定 maccms 短剧采集站 + 内置 TVBox 订阅支持（用户可加源）。剧立方现状已是这条路。
- **第二阶段**：路线 D + 自有源——热门剧建自有缓存/CDN，接触版权方授权（二轮剧/老剧）。
- **第三阶段**：向路线 A/B 转型，或做「短剧导航/推荐平台」不直接提供播放。

**关键风险**：直接提供盗版播放法律风险极高（有刑事判例）。建议定位「聚合播放器」而非「内容提供方」，源由用户自行配置（TVBox 空壳模式）。

## 三、对剧立方的直接结论

1. **红果只给前 3 集是产品策略**（网页引流版），不是我们能破解的技术 bug——已在 v1.1.7 优化报错文案引导用户「换一集或换源」。
2. **要看全集，正解是 TVBox/maccms 采集源**（采集站爬的是红果 App 端，有全集）——这正是剧立方「视频源」页已有的能力。**用户应优先用「视频源」看全集，「发现」页（红果）只作前几集预览/引流**。
3. 不必投入做红果签名机（路线 C）：技术复杂、极不稳定、法律风险高，不适合产品化。
